## Permanent-deletion approval boundary

The current head always references at least its immutable creation revision. Permanently deleting even an unused saved definition requires changing SQLite deletion guards and PostgreSQL INSERT-only revision retention, together with restrictive FKs. Counting current retained runs also cannot prove an agent was **never** used after those runs were legitimately purged. A safe future design needs an authoritative usage marker, conservative treatment of existing unknown history, strict server eligibility and transactional exclusion against run admission/editing. This requires a separately reviewed/approved retention migration. Do not implement a head-only tombstone and call it permanent deletion, or disable guards for convenience. Archive/reactivate remain operational now.
